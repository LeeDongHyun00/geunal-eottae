# 직군별 할 일

[개요](kickoff.md) v4를 기준으로, M0부터 출시 후 종료 판단까지 직군마다 할 일을 적습니다. 각 단계는 앞 단계의 게이트를 통과해야 시작합니다([개요](kickoff.md) 8장). 파트마다의 완료 조건은 각 파트 문서의 마지막 장에 있습니다.

## 3. M1 캘린더 알파

게이트: 내부 테스터 10명이 2주 동안 써서 캘린더 활성 50% 이상, 추천 입력 비율 30% 이상, 크래시 없는 세션 99.5% 이상, 기기 캘린더 가져오기 성공 90% 이상, 복구 코드로 새 기기 복원 100%.

| 디자인 | M1 화면 시안(온보딩, 월·주·목록, 빠른 입력 시트, 일정 편집, 교대 템플릿, 사람·생일, 설정, 위젯). 앱 아이콘 초안. UX 문구. M2 와이어프레임(그룹 캘린더, 날 테이블, 날짜 잡기, 투표, 그룹 설정) | Claude 시안, 사용자 확정 |

**알파 통계:** 추천 입력 비율은 기기 안에서만 알 수 있습니다. 알파 빌드에만, 동의한 테스터의 기기가 하루 한 번 숫자(앱을 연 횟수, 새로 만든 일정 수, 그중 추천으로 만든 수, 비정상 종료 수)만 보냅니다. 공개 빌드에는 넣지 않습니다. 캘린더 활성은 앱을 연 날로, 크래시 없는 세션은 앱을 연 횟수와 비정상 종료 수로 셉니다([공통 계약](parts/protocol.md) 14장).

**판단 시점:**
- **D+3개월:** 월 순매출 20만 원이 목표입니다. 못 미치면 가격·혜택·홍보를 바꿉니다.
- **D+6개월:** 월 순매출이 서버비(월 약 9만 원)에 못 미치면, 스테이징을 반납해 비용을 줄이고 혜택을 다시 정합니다.
- **D+12개월:** 그동안 순매출이 한 번도 없었다면 아래 절차로 종료합니다.

**종료 절차:**
1. 30일 전에 앱 안과 스토어에 공지하고, 신규 가입과 구독 판매를 멈춥니다.
2. 남은 구독은 갱신을 끄고, 스토어 규칙에 따른 환불을 안내합니다.
3. 마지막 업데이트를 냅니다. 그룹·채팅·백업을 끄고 개인 캘린더는 서버 없이 계속 쓰게 두며, 캘린더 내보내기(ICS)를 넣습니다. 일정의 원본이 기기에 있어서 가능한 일입니다.
4. 종료일에 서버 데이터(계정, 우편함, 상태, 첨부, 백업)를 지웁니다. 접속 로그와 관리자 접근 기록처럼 법정 보관 기간이 남은 것은 그 기간이 지난 뒤 지웁니다.
5. NCP 자원을 반납하고(Terraform으로 모두 삭제, Micro 반납), 도메인 갱신을 멈추고, 스토어에서 앱을 내립니다.
6. 사업자 폐업과 부가통신사업 폐지를 신고합니다.
