## 알아 둘 것

- QA는 남의 PR을 구독하지 않고 리뷰만 남깁니다. 같은 GitHub 계정이라 승인·변경 요청은 못 하고 COMMENT로 남깁니다. 리뷰의 `commitID`는 `git ls-remote origin refs/pull/N/head`의 전체 SHA를 씁니다.
- 공개 저장소입니다. 보안 결함은 공개 리뷰에 "고칠 것 하나를 따로 전했다"까지만 쓰고, 세부와 재현은 조정 세션에 `send_message`로 보냅니다. 재현 방법(어떤 값을 바꾸면 막히는지)도 공개 리뷰에 쓰지 않습니다. 제출한 리뷰 본문은 MCP로 고칠 수 없습니다.
- Caddy 동작은 `caddy:<버전>` 이미지를 `--network host`로 띄워 재현할 수 있습니다(오류 로그의 요청 주소, `X-Forwarded-For` 처리를 이렇게 확인함).
- 코어 동작은 PR 머리에서 `git worktree`를 만들고 `fake.rs`에 시험용 도우미를 더해 `cargo test -p geunal-sync --test engine <이름>`으로 확인했습니다. 푸시하지 않고 worktree를 지웁니다.
- 로컬 `main`은 `origin/main`과 공통 조상이 없습니다(저장소 이력이 바뀐 적 있음). 브랜치는 `origin/main`에서 만듭니다.
- m1.md 2.6 대조는 표의 백틱 이름을 모두 뽑아 시험 소스에서 `git grep -F`로 찾는 방식입니다.
- 안드로이드 API 26–30의 `KeyStore.getKey`가 null이면 데몬 무응답일 수 있습니다. 읽을 때 키를 만들면 비밀을 모두 잃습니다(#63).
- 코어 오류 문구에 URL이 실리지 않게 reqwest 오류는 `without_url()`로 바꿉니다(#56, #71).
